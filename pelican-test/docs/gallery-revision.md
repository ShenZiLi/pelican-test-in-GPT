# 多画幅穿行修订

2026-10-25，用户以 Superman in Flight 的实际播放画面指出：需要同时看见多个独立画幅，角色在画幅之间穿梭。此修订替换原来的满屏左右擦除调度。参考仅用于理解呈现方式；场景、角色、代码、音乐继续使用本项目原创实现。

## 画面与运动

- 固定视频为1920×1080；画幅600×600，间隔42，顶边145。通常同时可见三个完整画幅或两个完整画幅及两侧局部。
- 浏览器按可用宽高动态展开长展墙，宽屏可看见更多相邻作品。没有横向页面滚动条；底部拖杆只用于时间定位。
- 唯一骑手在展墙世界坐标中向右移动，每6秒前进642单位。镜头在每幅前3.5秒停留，让骑行和笑点可读，最后2.5秒平滑追向下一幅。过框强拍有1.2%的短促推近。
- 背景与透明角色层分开。相邻作品的角色绘法在各自画框内裁切，框外空白由同一骨骼的素描绘法连接，因此跨边界时能同时看到两种笔法，而非整屏换图。
- 20个场景导出独立的 `renderSubject`，背景可以关闭角色。不同笔法、皮影杆、像素量化、GIF低帧、阴影、示波器余辉和SVG绘制均保留。
- 采用原场景x=0..1000方幅视窗。岩画牛群与牧人、玛雅计圈、莫卧儿宾客、示波器控制、聊天窗口和代码区已重排入画；题名在画幅下方统一显示中英文及年代，局部裁切题字已移除。
- 14→15仍在89秒通电；像素金币/坑洞按新的横向骑行位置校正。音乐时序不变。
- Outro先从最后一组画幅拉远到7×3全墙，随后推到第21格；结尾骑手经过、车铃与空席保持原时序。

## 检查方法

`node --test` 覆盖多幅可见性、逐幅下拍、角色世界位置与镜头连续性，并保留原骨骼和音频检查。`node tools/verify-gallery.mjs` 在实际Chrome中检查20透明角色层、同一时点顺序/乱序绘制、边界帧，并输出无角色背景接触表供视觉复核。

完整重建：`node tools/render.mjs --from 0 --to 137 --fps 60 --name gallery-final --audio exports/audio/pelican-score.wav`，再运行 `node tools/finalize.mjs`。最终验收以更新后的delivery文件及记录为准；旧版单幅导出仅保留作工作过程记录。
