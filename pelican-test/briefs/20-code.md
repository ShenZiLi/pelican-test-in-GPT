## 真实SVG与逐笔因果

左侧固定8行可读SVG `<use href="#…"/>`，不高速滚屏；完整路径定义折叠。导出的 `pelicanSVG` 包含完全相同的8组定义和这8行use引用。Canvas、源码与导出均消费同一份路径图，不以假代码描述另一只鸟。

## V2 创意重制

代码美学 · 01:59–02:05 · P0

- **已呈现：** 深色编辑器、真实SVG结构、逐步生成轮子→车架→鸟体，非纯静态装饰代码。

- **偏差：** 120–121秒绘制中的鸟车压在代码栏上，预览区却大半空着；代码滚动密、字小，观众看不清代码与形状的对应。完整造型出现后很快挤向出口，成品仍是前面那只光滑鸟，未成为高潮。

- **0–2秒：** 清爽双区布局，左侧只显示当前相关的6–8行可读SVG；右侧从车轮开始，一行高亮对应一条路径落笔。

- **2–4秒：** 依次完成车架、长喙、喉囊、颈部、翼羽、眼神；强调有节奏的轮廓与精致局部，全部位于预览区内。原始路径详情可折叠，避免高速滚屏。

- **4–6秒：** 至少留0.75秒完整作品展示，再让绘好的鸟开始踩踏，预览区与外画框出口接通，骑进新闻发布会。

- **验收：** 代码与落笔存在可辨因果；绘制不压代码；最后姿态是经单独设计的高完成度鹈鹕，轮、脚、羽、喙均经近景检查；完整作品有停留时间。

实际目标画幅1920×840，画中正方形1000单位，以最终600像素展示检查笔触、表情、道具和标题。0.5、2.5、5.5秒关键帧用于验证布局，不以代码通过替代实际画面。
